# Project Instructions for Claude

You are working on my existing Next.js portfolio/project-selling website.

## Main Goal

Improve the UI/UX and business presentation of this project without changing the project structure.

This website is for:
- My web developer portfolio
- Project-based part-time work
- Selling my ready-made projects
- Selling web development courses
- Running live training programs as a web developer trainer
- Showing services, project demos, pricing/packages, and contact/inquiry options

## Very Important Rules

Do not change project structure.
Do not rename folders.
Do not rename routes.
Do not change backend/API/auth logic.
Do not change database logic.
Do not remove existing functionality.
Do not install new packages unless I approve first.
Do not update package versions.
Do not redesign from zero.
Do not make random large refactors.
Only improve UI, layout, content flow, responsiveness, typography, spacing, and Bangla/English friendly presentation.

## Token Saving Rules

Before reading many files, first inspect only important files:
- package.json
- app/page.tsx
- app/layout.tsx
- app/globals.css
- components/**
- lib/**
- data/**
- constants/**
- config/**
- tailwind.config.*
- next.config.*

Do not read:
- node_modules
- .next
- build/dist/out folders
- .env files
- images/videos/uploads
- zip/pdf/archive files
- lock files unless absolutely needed

When working, make small focused changes.
Do not scan the whole project unnecessarily.
First explain your plan, then wait for my approval before making big UI changes.

## UI/UX Improvement Goal

Make the website look:
- Professional
- Modern
- Clean
- Trustworthy
- Developer-brand focused
- Mobile responsive
- Bangla and English friendly

Improve:
- Hero section
- Services section
- Ready projects section
- Course section
- Live training section
- Portfolio/case studies
- Work process
- Why choose me
- FAQ
- Contact/inquiry CTA

- Project customization

- Web development course

Use clear CTAs:
- Hire Me

## Bangla/English Support

If language support already exists, use the existing system.
If translation objects already exist, improve them carefully.
If no language system exists, do not add complex i18n without asking.
Keep content easy to convert between Bangla and English.

## Workflow Check

Before changing UI, compare the current project flow with the business goal and find:
- Missing sections
- Weak CTA
- Confusing content
- Poor mobile layout
- Repeated content
- Bad spacing
- Unclear project-selling flow
- Unclear course/training flow

Then suggest improvements.

## Final Response Format

After any change, explain:
- Files changed
- What was improved
- What was not changed
- Any issue found
- Next recommended step
